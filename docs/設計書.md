# アンペア消費可視化アプリ 設計書

## 1. 目的と設計方針

「アンペア消費可視化アプリ 要件定義書」に基づき、初期リリースの実装構造、データ形式、集計規則、画面状態および確認方法を定める。

- Next.js App Router 上の単一画面として実装する。
- 家電カタログはリポジトリ内のCSVを初期値として読み込み、利用者の変更はReactのメモリー上だけに保持する。
- 集計の内部単位は0.1Aを表す整数とし、浮動小数点演算による表示・比較誤差を避ける。
- CSVは全件を読み込み・検証し、エラー時に部分的なカタログや合計値を表示しない。
- グラフに加え、状態・数値・家電一覧で同じ情報を確認できるようにする。
- 既存のダークモードと共通ヘッダーは維持する。テーマ設定の保存は、アンペア設定および家電データの一時保持とは別に扱う。

## 2. 対象範囲

### 2.1 初期リリースで実装する機能

- 上限値の入力と検証（初期値20.0A、0.1A刻み、最大60.0A）
- CSV家電カタログの読み込みと厳密な検証
- 家電の追加・編集・削除
- 家電ごとの有効状態および起動中状態の切り替え
- 有効な家電のアンペア数集計、残り／超過量表示
- 家電別上位10件と「その他」を示す積み上げ横棒グラフ
- ロード中、CSVエラー、家電0件、上限到達・超過状態の表示
- 入力とグラフのキーボード操作およびスクリーンリーダー対応

### 2.2 初期リリースでは実装しない機能

- データベース、サーバーAPI、Cookie、localStorage、sessionStorageへの家電・上限値の保存
- 電力計やスマートプラグとの連携、家電の自動制御
- 200V家電、個別回路・相線別の集計、電気料金・電力量の計算
- ブレーカー遮断の予測または保証
- グラフ表示用の外部チャートライブラリ

## 3. アプリ構成

### 3.1 データフロー

1. `/` を開くと画面はCSVを取得し、全行を解析・検証する。
2. 全件が有効な場合だけ、初期家電と初期上限値20.0Aを画面状態に設定する。
3. 読み込みに失敗した場合はエラーと再試行操作を表示し、家電一覧・合計・グラフを表示しない。
4. 利用者の操作はクライアント側状態を更新し、集計値と画面表示を同じ状態から再計算する。
5. ページを再読み込みすると、変更は破棄され、CSVと初期上限値から再開する。

```text
public/data/appliances.csv
          │ fetch + strict parse
          ▼
AmpereDashboard (React state)
   ├── AmpereSummary ── limit / total / remaining or excess
   ├── AmpereStackedBar ── top 10 + other + limit marker
   └── ApplianceList ── enable / starting / edit / delete
          ▲
   ApplianceForm ── add / edit

pure domain helpers
   ├── csv.ts         CSV parsing and catalog validation
   ├── validation.ts  amp/name/limit validation
   └── calculations.ts exact aggregation and graph groups
```

### 3.3 既存機能との関係

- `src/app/page.tsx` のSQLiteメッセージ取得表示をアンペア状況画面に置き換える。
- 共通レイアウト、`Header`、`DarkModeProvider`、テーマ切り替えは維持する。
- SQLiteメッセージのデモ機能は不要になるため、`lib/database.ts`、`/api/message`、`src/types/api.ts` を削除する。
- デモ機能にのみ使われている場合は `better-sqlite3` と `@types/better-sqlite3` も依存から外し、ロックファイルを更新する。
- SQLite/API関連テストを削除し、ホーム画面のテストをアンペア画面の振る舞いに置き換える。READMEからSQLiteメッセージ取得・DBセットアップ・API説明を除き、アプリ概要を更新する。
- アプリ名・メタデータの変更は、画面実装と合わせて必要性を確認する。

## 4. データモデル

### 4.1 アンペア値

内部では0.1Aを1単位とする整数で保持する。例: `12.3A` は `123`、`0.0A` は `0`。

画面表示時のみ整数を10で割り、小数第1位と単位 `A` を付ける。入力値はまず文字列として受け、検証成功後に整数へ変換する。上限値は1〜600（0.1A単位）、家電の運転中・起動時値は0以上とする。家電値に上限60Aを流用しない。

10進文字列は、0.1A単位に正確に変換できることを検証する。小数第2位以降がある場合はすべて0である値（例: `2.50`）を許容し、`2.05` は拒否する。指数表記、NaN、Infinity、負数は拒否する。変換後の整数は安全な整数範囲内であることも確認する。

### 4.2 家電

```ts
type Appliance = {
  id: string;
  name: string;
  runningAmpsTenths: number;
  startupAmpsTenths: number | null;
  enabled: boolean;
  starting: boolean;
  note: string;
  origin: 'catalog' | 'user';
};
```

- CSV行には `name`、`runningAmps`、`startupAmps`、`initiallyEnabled`、`note` を持たせる。
- CSV行番号から初期レコードの一意なIDを生成する。利用者追加時は名前ではなく一意なIDを生成し、同じ名前を複数登録できるようにする。
- `initiallyEnabled` を `enabled` の初期値に反映する。CSV初期値はすべて無効。
- `starting` の初期値は常に `false`。有効状態とは独立した状態として扱い、どちらの切り替えも他方を自動変更しない。
- `startupAmpsTenths` が `null` の家電を起動中にしても運転中値を使い、起動時参考値が未登録である旨を表示する。
- `note` はCSVの参考注記および利用者入力の任意メモに使う。注記は値の正しさや製品仕様を保証しない。

### 4.3 画面状態

CSVロード段階と失敗状態で集計値を誤表示しないよう、状態を判別可能な形で管理する。

```ts
type DashboardState =
  | { status: 'loading' }
  | { status: 'error'; message: string }
  | {
      status: 'ready';
      appliances: Appliance[];
      limitAmpsTenths: number;
    };
```

フォームの編集中の文字列や検証エラーはフォーム内で別に管理する。確定済み状態は有効な値だけを保持し、無効な入力は確定値に反映しない。

## 5. CSV形式とロード規則

### 5.1 配置と列

ファイルは `public/data/appliances.csv` とし、画面から `/data/appliances.csv` を取得する。ヘッダーは次の順序・名前を固定する。

```csv
name,runningAmps,startupAmps,initiallyEnabled,note
冷蔵庫,2.5,,false,450L級を想定した目安。容量・機種で差がある。
```

- UTF-8を使用し、UTF-8 BOMの有無およびLF/CRLFを許容する。
- カンマ・引用符・改行を含むフィールドはCSV標準の二重引用符規則で扱う。
- `startupAmps` の空欄は未登録を表す。`runningAmps` は必須。
- `initiallyEnabled` は小文字の `true` または `false` のみを許容する。
- 初期カタログは要件定義書にある12種類を含み、すべて `false` とする。値と注記は要件定義書の暫定参考値に一致させる。
- 参考アンペア値は100V基準の一般的な目安であり、製品ごとの定格・実測値または保証値ではない。定期・自動更新はせず、CSV変更時に手動で見直す。

### 5.2 全件検証

以下のいずれかに該当した場合、読み込み全体を失敗とし、CSV行番号またはファイル全体のエラー原因を表示する。

- fetch失敗、HTTPエラー、空ファイル、ヘッダーの不足・重複・順序違い
- CSV構文エラー、列数不一致、家電名の空欄、アンペア値の不正
- `initiallyEnabled` の許容値外、初期家電数が50件を超える

不正行を除外して継続したり、エラーを空配列に置き換えたりしない。検証は全行に対して行い、成功した場合だけ初期状態へ反映する。表示するエラーは修正対象を説明し、CSV取得の再試行操作を提供する。

## 6. 入力・操作仕様

### 6.1 上限値

- 初期値は20.0A。入力は正の数値、有限値、0.1A刻み、60.0A以下であること。
- 有効値だけを確定状態に反映し、無効時は直前の確定値を維持する。
- エラーは入力欄に関連付けて表示し、0A以下・60A超・0.1A刻み以外などの修正方法を示す。
- Enterまたは明示的な適用操作で確定する。無効値の間も確定済みの集計値とグラフは維持する。

### 6.2 家電の追加・編集・削除

- 追加を含め登録上限は50台。CSV初期分と利用者追加分を合算して数える。
- 50台到達時は追加操作を無効化または拒否し、理由を表示する。編集は台数を増やさない。
- 家電名は必須。運転中値は必須かつ0以上0.1A刻み、起動時値は任意かつ入力時は0以上0.1A刻み。
- 編集時は同一レコードのIDと状態を維持し、削除時は該当IDのレコードのみ除く。
- 家電一覧とフォームでは100V家電のみが対象であることを案内する。200V家電の値を100V換算する機能は作らない。
- 起動中と有効状態は別のスイッチとして一覧から操作できる。起動中状態は無効な家電にも保持できるが、無効な家電の値は集計・グラフに含めない。
- 保存は行わない。リロード後はCSV初期値に戻る。

## 7. 集計・グラフ仕様

### 7.1 集計

各家電の集計値は整数の0.1A単位で求める。

```text
無効家電                         -> 0
有効かつ通常運転中               -> runningAmpsTenths
有効かつ起動中・起動時値あり     -> startupAmpsTenths
有効かつ起動中・起動時値なし     -> runningAmpsTenths
```

合計、残り、超過量も整数で計算する。

```text
remaining = limit - total
remaining > 0  -> 上限内、残りを表示
remaining = 0  -> 上限到達
remaining < 0  -> 上限超過、超過量は -remaining
```

家電状態・値・上限値の確定更新後、単一のReact状態から合計・状態表示・グラフ区分を再計算する。別々に更新される状態値として合計を二重保持しない。

### 7.2 積み上げ横棒

- 有効家電を現在の集計値の降順に並べ、先頭10件を個別区分、残りを「その他」にする。10件以下ならすべて個別表示する。
- 同値の場合は家電名、続いてIDで順序を決める。
- 「その他」の値を含め、棒の全区分の合計は数値表示の合計と一致させる。
- 凡例は各区分の名前と値を示し、「その他」は合算値を表示する。
- HTML/CSSで積み上げ棒を描画し、絶対配置の上限マーカーと目盛りを添える。色だけに依存せず、凡例・値・テキストを併用する。
- 軸上限は `max(合計, 上限) × 1.1` 以上となるよう1A単位で切り上げる（最低1A）。これにより合計超過時も棒と上限マーカーの両方を範囲内に表示する。
- グラフ領域に合計・上限・状態を含む読み上げ用説明を付ける。数値サマリーと家電一覧はグラフと同じ情報のテキスト代替とする。
- 合計0Aでも合計値・上限マーカー・一覧を表示し、「使う家電を有効にすると合計に反映されます」と案内する。
- 上限超過時は画面内バナーで超過量を示す。モーダルや自動的な家電状態変更は行わない。

## 8. 画面構成・アクセシビリティ

上から次の順に表示する。

1. 画面タイトルと、100V基準・回路別集計なし・遮断保証なしの常時注意書き
2. 上限設定入力と、リロードで初期化される旨の控えめな説明
3. 合計、上限内／到達／超過の状態、残りまたは超過量
4. 上限マーカー付き積み上げ横棒と凡例
5. 家電追加操作および家電一覧（有効・起動中・値・編集・削除）
6. 家電の追加・編集フォーム（ページ内フォームまたはダイアログではないインライン領域）

- 上限内・到達・超過は色に加えて文字およびアイコンで判別できるようにする。
- 操作要素は可視ラベル、フォーカス表示、キーボード操作を備える。状態切り替えの名称には対象家電名と状態を含める。
- エラー文は該当入力に `aria-describedby` などで関連付け、エラー状態を色だけで伝えない。
- 起動時値が未登録の家電が起動中の場合、運転中値を代用している説明を一覧に表示する。
- 画面幅が狭い場合は凡例・一覧を折り返し、主要数値と操作を横スクロールなしで確認できるようにする。
- 「100V家電」「家全体の目安」「実際の遮断を保証しない」ことを常時表示する。

## 9. エラー表示

| 状況 | 表示・動作 |
|---|---|
| CSV取得・解析・検証失敗 | エラー原因、修正箇所、再試行を表示。合計・グラフは表示しない。 |
| 上限値が不正 | 入力欄付近に具体的な修正案を表示。直前の確定上限と集計を維持。 |
| 家電入力が不正 | 対象欄のエラーを表示し、保存しない。 |
| 50台到達 | 追加を拒否し、登録上限に達した旨を表示。既存データは変更しない。 |
| 起動時値が空欄 | エラーにはせず、起動時に運転中値を使うことを表示。 |
| 有効家電なし | エラーにはせず、合計0Aと操作案内を表示。 |

既存のJestおよびReact Testing Libraryを利用し、少なくとも次を確認する。

### 10.1 単体テスト

- 10進文字列から0.1A単位への変換、`2.50` の許容、`2.05`・指数表記・非有限値・負数の拒否
- 上限値の境界（0、0.1、60、60超）と刻み不正
- CSVの正常行、引用符・カンマ・CRLF・BOM、および不正ヘッダー・列数・数値・ブール値・空名

- 上限内・到達・超過と残り／超過量

- 初期上限20Aと全無効のカタログを表示すること

## 11. 検討事項と決定事項

### 11.1 ユーザー確認済みの決定

| 項目 | 決定 |
|---|---|
| 利用者が追加した家電の初期有効状態 | 新規追加時は「使用中」をON、「起動中」をOFFにする。追加直後から合計に反映する。 |
| 200V家電の登録抑止 | 電圧入力欄は追加せず、フォームと常時注意書きで100V家電のみを対象と案内する。 |
| SQLiteメッセージのデモ機能 | アンペア画面への切り替えに合わせ、関連コード、API、型、専用テスト、README記述を削除する。ほかに利用箇所がなければ関連するSQLite依存も外す。 |

200V家電は入力値から自動判定されないため、画面上の案内だけでは誤登録を技術的に防止できない。この制約は初期版の既知事項とし、入力時の対象案内と常時注意書きで明示する。自動抑止が必要になった場合は、電圧項目の追加を仕様変更として検討する。

### 11.2 実装時の設計前提

| 項目 | 方針 |
|---|---|
| CSV列の将来変更 | 本書で定義した固定ヘッダーを初期スキーマとし、変更時はパーサー・CSV・テストを同時更新する。 |
| 上位10件の同値順序 | アンペア値が同じ場合は家電名、続いてIDの順にし、表示順を決定する。 |

仕様を変更する場合は、本書だけでなく要件定義書も合わせて更新する。

## 12. 注意事項

本画面の集計は利用者が登録した100V家電のアンペア目安を合算するものである。実際の電気設備、契約容量、回路構成、電圧変動、力率、同時起動条件を測定するものではない。上限以下でもブレーカーが落ちないことを保証せず、上限超過が直ちに危険または遮断を意味するものでもない。設備の判断には仕様確認を行い、必要に応じて有資格者へ相談する。
